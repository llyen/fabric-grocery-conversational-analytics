# Conversational analytics in Microsoft Fabric: e-grocery demo

[Polska wersja](README.md)

A self-contained Microsoft Fabric demo built around Northwind Traders, a fictional online grocery that delivers by van to six Polish cities from three warehouses. It shows the same operational questions answered three ways: a Power BI report, a Fabric Data Agent that answers in natural language (Polish), and a small Fabric-hosted web app built with Rayfin.

> **Disclaimer.** Northwind Traders is fictional. All warehouses, suppliers, products, volumes and incidents are generated by `generate_data.py` and do not describe any real company. This is a personal demo project, not an official Microsoft sample, and it is provided as is.

## Architecture

```
generate_data.py ──► data\*.parquet ──► Lakehouse (15 Delta tables)
                                            │
                                            ├─► Semantic model (Direct Lake, 17 relationships, 32 KPI measures)
                                            │       ├─► Report (PBIR, 4 pages)
                                            │       └─► Data Agent (model + lakehouse SQL endpoint)
                                            │
app\scripts\build_snapshot.py ──► app\src\data\snapshot.json ──► Rayfin web app (Fabric AppBackend)
```

| Item | Name | Purpose |
|---|---|---|
| Lakehouse | lh_northwind_demo | 15 Delta tables: dimensions, operations, IT load log |
| Semantic model | sm_northwind_operacje | Direct Lake, 17 relationships, 32 KPI measures |
| Report | rpt_northwind_operacje | On-time delivery, stock-outs and substitutions, fresh-food write-offs, data freshness (IT) |
| Data Agent | agent_operacje_northwind | Sources: model and lakehouse, Polish instructions, 7 example SQL queries |
| Rayfin app | northwind-operacje | Dashboard, signals, action board, data loads, prepared agent questions |

The scenario's "today" is 28 Oct 2026 and the data covers 3 Aug to 27 Oct 2026. Several stories are planted in the data (afternoon traffic in Rzeszów, a picking bottleneck in the Lublin distribution centre, a supplier shortage, a cold-chain break, a WMS schema change, an incomplete TMS load). They are listed in the Polish README. The UI, report and agent are in Polish.

## Requirements

- A Microsoft Fabric capacity and permission to create workspaces in its tenant
- Azure CLI, signed in with `az login`
- Python 3.12+ with `pandas`, `pyarrow`, `requests`, `pyodbc`
- ODBC Driver 18 for SQL Server (used to validate the agent's example queries)
- Node.js 20+ and npm for the Rayfin app

## How to reproduce

```powershell
pip install pandas pyarrow requests pyodbc
python generate_data.py                                # optional: data\*.parquet is committed; the generator is deterministic
$env:FABRIC_CAPACITY_ID = "<fabric-capacity-id>"       # required
$env:FABRIC_WORKSPACE_NAME = "Northwind Traders demo"  # optional
cd deploy
python 01_workspace_lakehouse.py   # workspace, lakehouse, upload, Delta tables
python 02_semantic_model.py        # model, measures checked against data\_kontrolne.json
python 03_report.py                # PBIR report with field validation
python 04_data_agent.py            # validates few-shot SQL on the SQL endpoint, deploys the agent
```

Deployed item IDs are written to `.fabric\deployment.json` (git-ignored). Publishing the Data Agent is not available through the API, so open it in the Fabric portal and select Publish.

### Rayfin app

```powershell
cd app
copy .env.example .env             # fill in the report and Data Agent IDs
python scripts\build_snapshot.py   # rebuild the snapshot after changing data
npm ci
npx rayfin login --tenant <tenant>
npx rayfin up --workspace-id <workspace-id> --tenant <tenant> -y
npm run build
```

On the first deployment run `rayfin up` twice; the first run may report a SQL database name conflict and it also creates `rayfin\.env`, which `npm run build` needs to embed the backend endpoint. Reads come from the static snapshot; only user writes (actions, incident acknowledgements) go to the Rayfin database. The browser cannot call the Data Agent directly, so "Zapytaj agenta" copies the question and opens the agent in the Fabric portal.

Pause the capacity when you are done, as it is billed while running.
